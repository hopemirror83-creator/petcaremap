# SEO 정보 사이트 품질 템플릿

이 문서는 공공데이터, 검색 API, 지도 API, 후기 후보, AI 요약을 결합해 SEO형 정보 사이트를 만들 때 사용하는 기본 지침서입니다.

목표는 단순 DB 목록 사이트가 아니라, 검색 사용자가 방문 전 의사결정을 할 수 있도록 돕는 정보 사이트입니다.

## 1. 사이트 목표

사이트는 실시간 검색 도구가 아니라 정적 SEO 자산입니다.

핵심 목표는 다음과 같습니다.

- 전국 또는 지역 단위 데이터를 확보한다.
- 업체 상세페이지와 지역/유형 묶음 페이지를 함께 만든다.
- 검색자가 방문 전 판단할 수 있는 정보를 제공한다.
- 네이버와 구글에서 지역+롱테일 키워드로 노출될 수 있게 구성한다.
- 처음부터 전국 확대보다, 샘플 지역에서 품질을 검증한 뒤 확장한다.

## 2. 기본 진행 순서

1. 공공데이터 또는 원본 데이터 확보
2. 네이버 검색 API 또는 관련 검색 API로 업체명, 주소, 후기 후보 보강
3. 지도 API로 실제 장소명, 위치, 지도 URL, 전화번호, 운영정보 보강
4. 블로그, 카페, 검색 스니펫 등 후기 후보 수집
5. 후기 원문을 저장하지 않고 제목, 요약, 링크, 출처만 저장
6. AI는 글 작성자가 아니라 후기 분석기로 사용
7. 상세페이지, 지역 허브, 유형 허브, 내부링크 생성
8. sitemap, robots, 수동색인 URL 파일 생성
9. 샘플 페이지 품질 확인 후 배포
10. 색인 반응을 보고 전국 확대

## 3. 데이터 구조 원칙

기본 데이터와 보강 데이터를 분리한다.

필수 테이블 또는 데이터 그룹:

- business: 업체 기본정보
- business_search: 검색 API 매칭 정보
- business_map: 지도 API 장소 정보
- business_review_source: 후기 후보 링크
- business_ai_summary: AI 분석 결과
- business_service: 서비스/진료/편의 항목
- business_relation: 내부링크 관계
- region_pages: 지역 허브 페이지
- manual_index: 수동색인 대상 URL

## 4. 페이지 생성 조건

조건을 만족하지 못한 페이지는 draft로 둔다.

권장 published 조건:

- 주소가 정상이다.
- 지도 URL이 있다.
- 전화번호가 있다.
- 검색 또는 지도 매칭이 됐다.
- 후기 후보 또는 지도 리뷰 수 같은 공개 후기 지표가 있다.
- AI 분석 결과가 있다.
- 내부링크가 연결됐다.

조건이 부족하면 억지로 긴 글을 만들지 않는다.

## 5. 상세페이지 기본 구조

상세페이지는 아래 순서로 구성한다.

1. 상단 Hero
   - 업체명
   - 지역
   - 카테고리
   - 주소
   - 전화번호
   - 운영시간
   - 지도 바로가기
   - 후기/리뷰 배지

2. 후기 요약
   - 한 줄 요약
   - 후기 자료가 충분한지 여부
   - Hero 바로 아래에는 후기 분석 신뢰 문구를 넣는다.

   예시:

   ```text
   AI는 공개 후기 26건을 기준으로 반복 언급된 특징을 요약했습니다.
   블로그·카페 후기 제목과 요약, 지도 리뷰 수처럼 공개적으로 확인 가능한 자료만 참고합니다.
   ```

3. 공개 후기 분석
   - 지도 리뷰 수
   - 블로그 후기 수
   - 카페 후기 수
   - 참고 링크 수

4. 많이 언급된 내용
   - 후기 분석 카드는 텍스트만 쓰지 말고 아이콘, 항목명, 별점, 짧은 설명을 함께 표시한다.
   - 사용자가 한눈에 비교할 수 있게 5~8개 카드로 제한한다.

   예시:

   ```text
   AI 후기 분석
   공개 후기 분석 결과

   😊 친절한 설명
   ★★★★★

   🏥 시설
   ★★★★☆

   ⏰ 대기시간
   ★★★☆☆

   🚗 주차
   ★★☆☆☆

   📞 예약
   ★★★★☆
   ```

   기본 항목:

   - 친절한 설명
   - 시설/청결
   - 대기시간
   - 주차
   - 예약
   - 비용/과잉 여부
   - 서비스/진료/방문 목적

5. 업체 특징
   - 가능/불가/확인 필요를 빠르게 이해할 수 있도록 기호를 함께 표시한다.
   - `✔`, `△`, `❌` 같은 판정 기호를 사용한다.
   - 기호만 두지 말고 짧은 상태값도 같이 둔다.

   예시:

   ```text
   24시
   ❌
   확인 필요

   야간
   △
   확인 필요

   응급
   △
   확인 필요

   고양이
   ✔
   후기 언급

   강아지
   ✔
   후기 언급

   특수동물
   △
   확인 필요

   주차
   ✔
   가능성 있음

   예약
   ✔
   권장
   ```

6. 이 업체가 잘 맞는 경우
   - 사용자가 선택할 이유를 정리

7. 방문 전 확인할 항목
   - 예약
   - 운영시간
   - 주차
   - 접수 마감
   - 목적별 준비사항

8. 증상/상황 기반 검색 의도 박스
   - 사용자는 업체명보다 증상, 상황, 목적을 검색하는 경우가 많다.
   - 상세페이지 중간에 "이런 경우 많이 찾습니다" 박스를 자동 생성한다.
   - 실제 가능 여부는 병원이나 업체에 직접 확인하라는 짧은 안내를 붙인다.

   예시:

   ```text
   이런 경우 많이 찾습니다

   🐶 강아지 예방접종 상담
   🐱 고양이 건강검진
   🩺 중성화 상담
   🦴 슬개골·관절 상담
   🌙 야간·응급 상황
   🐢 거북이·햄스터·특수동물

   실제 진료 가능 여부와 당일 접수 가능 여부는 병원에 직접 확인하세요.
   ```

9. 검색 의도 내부링크
   - 지역 키워드
   - 동 단위 키워드
   - 서비스 유형 키워드
   - 주변 대안 키워드

10. 지도
   - 실제 지도 또는 지도 API 삽입
   - 지도 바로가기 버튼

11. 본문 콘텐츠
   - 기본정보
   - 후기에서 보이는 방문 목적
   - 처음 방문할 때 참고할 점

12. 비슷한 업체 비교
   - 현재 업체와 주변 업체를 표 또는 비교 카드로 보여준다.
   - 사용자가 여러 상세페이지를 오가지 않고 1차 판단을 할 수 있게 만든다.

   예시:

   ```text
   병원        후기      24시       주차       특수동물
   하얀기린    높음      확인 필요  가능성     확인 필요
   A병원       보통      가능       가능       가능
   B병원       보통      불가       불가       불가
   ```

13. 주변 대안
   - 같은 동
   - 같은 구
   - 같은 서비스 유형

14. FAQ
   - 예약
   - 주차
   - 운영시간
   - 서비스 가능 여부
   - 후기 확인 방법

15. 참고 링크
   - 블로그 후기
   - 카페 후기
   - 공식 홈페이지
   - 지도 링크

## 6. 후기 콘텐츠 원칙

후기는 직접 방문한 것처럼 쓰지 않는다.

좋은 표현:

- 후기에서는 ...라는 내용이 보입니다.
- 일부 보호자는 ...라고 언급했습니다.
- 검색 결과에서는 ... 관련 후기가 확인됩니다.
- 지도 리뷰에는 ...개의 리뷰가 표시됩니다.
- 블로그 후기에서는 ... 목적의 방문이 보입니다.

피해야 할 표현:

- 제가 방문해보니
- 확실히 좋습니다
- 최고입니다
- 반드시 추천합니다
- 완벽합니다

의료, 법률, 금융처럼 민감한 분야는 더 조심한다.

피해야 할 표현:

- 잘 치료한다
- 완치된다
- 진단이 정확하다
- 실력이 뛰어나다
- 효과가 좋다

대신 이렇게 쓴다.

- 관련 후기가 확인됩니다.
- 해당 목적의 방문 후기가 있습니다.
- 상담 시 확인하면 좋은 항목입니다.
- 방문 전 가능 여부를 확인하는 편이 좋습니다.

## 7. AI 역할

AI는 소개글 생성기가 아니라 후기 분석기다.

AI 출력 구조:

```text
한 줄 요약
후기에서 자주 언급된 내용
방문 목적
이 업체가 잘 맞는 경우
방문 전 확인할 항목
후기 부족 여부
FAQ 후보
```

AI에게 금지사항을 너무 많이 주면 글이 딱딱해진다. 대신 역할과 출력 구조를 명확히 준다.

## 8. AI 작성 프롬프트 기본형

```text
당신은 독자들이 쉽게 이해하고 공감할 수 있는 콘텐츠를 만듭니다.
정보 전달과 함께 독자의 관심을 끌 수 있는 글쓰기에 능숙합니다.
검색 최적화(SEO)를 고려하여 적절한 키워드를 자연스럽게 사용해 주세요.
한국인이 자연스럽게 읽는 표현을 사용해 주세요.

아래 자료를 바탕으로 업체 상세페이지 콘텐츠를 작성해 주세요.

역할:
- 직접 방문 후기가 아니라 공개 후기와 검색 결과를 분석해 전달합니다.
- 후기 원문을 복사하지 않고 요약합니다.
- 확인되지 않은 정보는 단정하지 않습니다.

작성 항목:
1. 한 줄 요약
2. 기본정보 설명
3. 후기에서 자주 보이는 방문 목적
4. 많이 언급된 장점 또는 특징
5. 방문 전 확인할 항목
6. 처음 방문하는 사람이 준비하면 좋은 것
7. FAQ 6개

문체:
- 친절하지만 과장하지 않습니다.
- "이런 후기도 있습니다", "후기에서는", "일부 보호자는" 같은 표현을 사용합니다.
- "최고", "완벽", "무조건 추천" 같은 표현은 사용하지 않습니다.
```

## 9. 후기 후보 수집 원칙

저장할 것:

- 제목
- 요약 또는 검색 스니펫
- URL
- 출처 유형
- 출처명
- 작성일이 있으면 작성일

저장하지 않을 것:

- 후기 원문 전체
- 로그인 필요한 비공개 내용
- 복사한 긴 문장

후기 후보가 있으면 참고 링크로 제공한다.

후기 후보가 부족하면 지도 리뷰 수, 위치, 전화번호, 운영 여부 중심으로 페이지를 구성한다.

## 10. 지역/롱테일 페이지 원칙

개별 상세페이지보다 지역/유형 묶음 페이지가 더 중요할 수 있다.

자동 생성할 페이지:

- 시/도 단위
- 시/군/구 단위
- 행정동 단위
- 서비스 유형 단위
- 지역+서비스 조합
- 지역+후기 조합
- 지역+추천 조합

예시:

- 인천 서해구 동물병원
- 인천 서해구 24시 동물병원
- 청라 동물병원 후기
- 가정동 동물병원
- 검단구 고양이 동물병원
- 서해구 예방접종 동물병원

## 11. 내부링크 원칙

상세페이지마다 아래 링크를 자동 연결한다.

- 같은 동 업체
- 같은 구 업체
- 같은 서비스 유형 업체
- 주변 대안
- 지역 허브
- 서비스 허브
- 후기 많은 업체
- 지도 리뷰 많은 업체

내부링크 텍스트는 검색어처럼 자연스럽게 만든다.

예:

- 인천 서해구 동물병원
- 가정동 동물병원
- 서해구 24시 동물병원
- 서해구 고양이 동물병원
- 서해구 예방접종 동물병원

## 12. UI 원칙

디자인은 조용하고 신뢰감 있게 만든다.

권장:

- 넓은 여백
- 큰 제목
- 카드형 정보
- 파란색 계열 포인트 컬러
- 모바일 우선
- 실제 지도
- 명확한 버튼

피하기:

- 과한 캐릭터 느낌
- 광고 랜딩페이지 같은 과장된 문구
- 정보 없는 긴 문단
- 똑같은 문장 반복
- DB 필드명을 그대로 노출

## 13. 상세페이지 품질 체크리스트

배포 전 아래 항목을 확인한다.

- 상단에서 업체명, 주소, 전화번호, 지도 버튼이 바로 보이는가?
- Hero 바로 아래에 "AI는 공개 후기 n건을 분석했습니다" 문구가 있는가?
- 후기 출처 수가 보이는가?
- 후기 분석 카드가 아이콘+별점+짧은 설명으로 보이는가?
- 업체 특징 카드가 `✔/△/❌` 판정으로 보이는가?
- 증상/상황 기반 "이런 경우 많이 찾습니다" 박스가 있는가?
- 현재 업체와 주변 업체를 비교하는 표 또는 카드가 있는가?
- 사용자가 선택할 이유와 확인할 이유가 구분되어 있는가?
- 지도 또는 지도 링크가 정상인가?
- FAQ가 검색 의도에 맞는가?
- 참고 링크가 하단에 있는가?
- 내부링크가 충분한가?
- "확인하세요"만 반복하지 않는가?
- "최고", "완벽", "잘 치료" 같은 단정 표현이 없는가?
- 모바일에서 카드와 텍스트가 깨지지 않는가?
- sitemap과 수동색인 URL이 생성되는가?

## 14. 추천 개발 우선순위

1. 샘플 2~5개 상세페이지 품질 완성
